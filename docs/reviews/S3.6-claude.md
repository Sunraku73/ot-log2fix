## 3. Dove il README (e il task) non bastavano

1. **Modello non scaricato ≠ "errore di comunicazione".** Il task lo metteva sotto `Errore di comunicazione con il provider`. In realtà Ollama risponde 404 e il CLI stampa `Errore provider HTTP 404`, che non suggerisce `ollama pull`. Il README ora ha una riga dedicata.
2. **"20-30 s su CPU" è falso su questa macchina.** Stessa richiesta del CLI, senza timeout:

   | Modello | GPU | Solo CPU (16 core) | Token generati |
   |---|---|---|---|
   | `qwen3:8b` | 8.4 s (CLI: 6–13 s) | 80.5 s, 118.2 s | 778–941 |
   | `qwen3:4b` | CLI: 3/3 exit 0, entro 60 s | 220.7 s, 252.6 s | 3126–3655 |

   Il client ha `timeout=60.0` fisso (`providers.py:54`): **solo CPU, la modalità locale fallisce sempre** (F51). Per una fixture di 14 righe la latenza è dominata dal ragionamento di qwen3.
3. **`qwen3:4b` non è "più leggero" in latenza.** Su CPU ragiona 3–4 volte più a lungo e impiega il doppio dell'8b. Il README lo presenta solo come opzione per GPU con poca memoria. Su GPU ha dato 3/3 la stessa diagnosi corretta dell'8b: "qualità inferiore" non è dimostrata su questa fixture semplice, quindi il README la presenta come aspettativa generale, non come misura.
4. **`.env` letto dalla directory corrente.** Con pipx il comando si lancia da ovunque: il README ora lo dice.
5. **PowerShell e Windows non provati** (nessuna macchina Windows). La sintassi `$env:` e `Invoke-RestMethod` è standard, ma pipx/ensurepath su Windows resta da verificare su un host reale.
6. **`--md` senza testo di aiuto** in `otlog2fix analyze --help` (F53).
7. **Nomi dei log OpenText:** segnaposto `TODO (maintainer)` nella sezione "Which logs to point at". Servono nomi e posizioni reali da Emilio prima del lancio.
